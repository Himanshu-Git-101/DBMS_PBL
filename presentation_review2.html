DELIVERABLE 1 • NORMALIZATION

Relational Normalization Up to 3NF

Systematic elimination of insertion, update, and deletion anomalies across the clinical schema

First Normal Form (1NF)
  • Atomic Domains: All table columns contain single scalar values.
  • Repeating Groups Decomposed: Multi-medication prescriptions extracted into prescription_items.
  • Diagnostics Extracted: Multi-test orders separated into test_orders associative bridge.
  • Primary Keys Identified: Unique surrogate keys guarantee tuple identity.
Second Normal Form (2NF)
  • 1NF Satisfied: No partial functional dependencies on composite candidate keys.
  • Prescription Details: prescription_id → date separated from item_id → dosage, frequency.
  • Diagnostic Details: test_id → standard_cost separated from order_id → result_value.
  • Every non-prime attribute depends on the entire candidate key.
Third Normal Form (3NF)
  • 2NF Satisfied: No transitive dependencies (X → Y, Y → Z).
  • Doctor & Dept Split: doctor_id → dept_id, while dept_id → dept_name, floor.
  • Ward & Bed Split: bed_id → ward_id, while ward_id → ward_type, capacity.
  • Every non-trivial functional dependency has a Superkey determinant.
DELIVERABLE 1 • DATA DICTIONARY

Concise Data Dictionary Across Modules

Structured schema specification defining primary keys, foreign keys, and domain checks

Outpatient & Scheduling
  • departments: dept_id (PK), dept_name (UQ), floor_number (CHECK ≥ 0)
  • doctors: doctor_id (PK), dept_id (FK), fee (CHECK ≥ 0), email (UQ)
  • doctor_schedules: schedule_id (PK), doctor_id (FK), CHECK(end > start)
  • patients: patient_id (PK), phone (UQ), dob (DATE), gender (CHECK)
  • appointments: appointment_id (PK), UQ(doctor_id, date, start_time)
Clinical & Diagnostics
  • consultations: consultation_id (PK), appointment_id (FK UQ 1:1)
  • diagnoses: diagnosis_id (PK), consultation_id (FK), icd10_code, severity
  • prescriptions: prescription_id (PK), consultation_id (FK), date
  • prescription_items: item_id (PK), prescription_id (FK), duration > 0
  • lab_tests: test_id (PK), test_code (UQ), standard_cost (CHECK ≥ 0)
  • test_orders: order_id (PK), consultation_id (FK), test_id (FK), status
Inpatient & Billing
  • wards: ward_id (PK), ward_name (UQ), ward_type (CHECK), capacity > 0
  • beds: bed_id (PK), ward_id (FK), bed_number, daily_rate ≥ 0
  • admissions: admission_id (PK), bed_id (FK), CHECK(discharge ≥ admit)
  • bills: bill_id (PK), CHECK(paid ≤ net), CHECK(net = total - disc + tax)
  • payments: payment_id (PK), bill_id (FK), amount_paid (CHECK > 0)
DELIVERABLE 2 • INTEGRITY VERIFICATION

Enforcing Critical Hospital Business Rules

Schema constraints, check predicates, and DDL triggers preventing clinical and financial collisions

1. No Overlapping Appointments
  • Trigger: trg_prevent_appointment_overlap
  • Enforcement Logic: Aborts insert if NEW.start_time < end_time AND NEW.end_time > start_time for active clinician appointments.
  • Result: Double-booking doctors is mathematically impossible.
WHERE doctor_id = NEW.doctor_id AND appointment_date = NEW.appointment_date AND (NEW.start_time < end_time AND NEW.end_time > start_time)
2. One Active Patient Per Bed
  • Trigger: trg_prevent_bed_double_booking
  • Partial Index: CREATE UNIQUE INDEX ON admissions(bed_id) WHERE status='ACTIVE'
  • Result: Disallows admitting a patient to a bed already housing an active inpatient.
WHEN NEW.status = 'ACTIVE' AND EXISTS ( SELECT 1 FROM admissions WHERE bed_id = NEW.bed_id AND status = 'ACTIVE')
3. Valid Admission / Discharge Dates
  • Check Constraint: CHECK (discharge_date IS NULL OR discharge_date >= admission_date)
  • Chronological Guard: Inpatients cannot have discharge timestamps earlier than their intake.
  • Result: Preserves valid duration of hospital stay.
4. Positive Charges & Payment Limits
  • Positive Checks: total_amount ≥ 0, amount_paid > 0
  • Payment Ceiling: CHECK (paid_amount ≤ net_payable)
  • Payment Trigger: Auto-updates paid_amount and transitions status to PAID.
DELIVERABLE 3 • SQL DEMONSTRATIONS

Multi-Table Joins & Advanced Subqueries

Relational queries extracting connected clinical narratives and benchmark analyses

Complex Multi-Table Joins
  • Longitudinal Clinical History (5 Tables): Joins patients → appointments → doctors → consultations → diagnoses to present complete diagnostic records.
  • Active Inpatient Census (6 Tables): Joins admissions → patients → beds → wards → doctors → departments with length of stay calculation.
  • Diagnostic Order Tracker (4 Tables): Joins test_orders → lab_tests → consultations → doctors with turnaround monitoring.
Scalar & Correlated Subqueries
  • Above-Average Billing Subquery:
    HAVING SUM(b.net_payable) > (SELECT AVG(net_payable) FROM bills)
    Filters high-utilization patients exceeding overall hospital benchmark.
  • Departmental Top Caseload: Correlated subquery identifying the busiest clinician per clinical department.
  • Vacant Bed Finder: Uses WHERE bed_id NOT IN (SELECT bed_id FROM admissions WHERE status='ACTIVE').
DELIVERABLE 3 • AGGREGATIONS

SQL Aggregations & Hospital Analytics

Analytical SQL queries with GROUP BY and HAVING calculating vital healthcare KPIs

Department Revenue Recovery
  • Aggregates encounters, gross billed amount, and actual collections per department.
  • Formula: (SUM(paid) / SUM(net)) * 100
  • Identifies top revenue generating wings (Cardiology & Surgery) and unpaid receivables.
ICD-10 Morbidity Statistics
  • Groups diagnostic encounters by ICD-10 classification codes.
  • Prevalence %: (COUNT(diag) * 100.0 / Total)
  • Highlights disease incidence (Unstable Angina, Type 2 Diabetes, Knee Osteoarthritis).
Ward Occupancy Census Rate
  • Ward capacity vs operational beds and active inpatients.
  • Occupancy %: (Active Beds * 100.0) / Total Beds
  • Daily Yield: SUM(daily_rate) for all currently occupied beds.
